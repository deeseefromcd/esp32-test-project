# esp32-test-project

Стенд герконовой сетки 4×4 для [Wokwi](https://wokwi.com) + **PlatformIO** на **ESP32-S3**:
клетка поля — залипающая кнопка (герконов в Wokwi нет), состояние читается через два
`74HC165` в цепочке — так же, как это будет на «умной шахматной доске». Светодиод мигает
одновременно с чтением сетки: один проект, одна схема, одна прошивка.

## Настройка с нуля

```sh
git clone https://github.com/deeseefromcd/esp32-test-project
cd esp32-test-project

make doctor     # что уже есть и чего не хватает (ничего не ставит)
make setup      # поставить зависимости
```

**Список зависимостей живёт в одном месте** — `Brewfile` и `make doctor`. Doctor
печатает для каждого недостающего инструмента точную команду установки, поэтому
дублировать список в документации не нужно: он бы разошёлся с кодом.

Один инструмент `make setup` не ставит — PlatformIO. Причина и рецепт:
[Особенность этой машины](#особенность-этой-машины-macos--python-315).

Дальше — `make help` (все команды) и `make check` (lint, тесты и сборка).
`WOKWI_CLI_TOKEN` в репозиторий не попадает: в CI он лежит в GitHub Secrets, а для
локального прогона (`make sim`) его достаточно держать в окружении, см.
[Синхронизация с Wokwi](#синхронизация-с-wokwi-github--симуляция).

## Схема

Схема собрана **на проводах, без макетной платы**: каждая связь — это провод между двумя
выводами, поэтому два разных узла не могут случайно оказаться на одном отверстии (на
макетной плате именно это и случилось — см. `design.md` в изменении `reed-matrix-stand`).

```
            ┌──────────┐   Q7 ── DS   ┌──────────┐
16 кнопок ──┤ 74HC165 ├──────────────┤ 74HC165 ├── Q7 ──► GPIO6
матрицей    │  (sr1)   │   PL, CP     │  (sr2)   │
4×4         └──────────┘ ◄── GPIO4/5 └──────────┘
   ▲ подтяжка 10 кОм на питание          ▲ земля второго контакта кнопки

ESP32-S3 GPIO48 ──► LED (анод) ──► LED (катод) ──► резистор 220 Ом ──► GND
```

Клетка читается через свою кнопку: сигнальный контакт — на вход регистра, второй контакт —
на землю, подтяжка 10 кОм — между входом и питанием. Замкнутая клетка тянет вход к земле и
читается низким уровнем; входы независимы, поэтому фантомных срабатываний не бывает
структурно (в отличие от матричного опроса строк и столбцов).

GPIO48 выбран потому, что на реальной плате ESP32-S3-DevKitC-1 на нём висит встроенный RGB-светодиод.
Три линии к корпусам — GPIO4 (`PL`), GPIO5 (`CP`), GPIO6 (`Q7`): свободные пины, не strapping
и не UART0.

## Запуск в VS Code (PlatformIO + Wokwi)

Порядок важен: **Wokwi не компилирует код — он запускает готовую прошивку.**

1. Установить расширение **PlatformIO IDE** в VS Code (даёт кнопку Build и терминал `pio`).

2. **Собрать прошивку** (из папки проекта):
   ```sh
   make build      # или: pio run
   ```
   Первый раз PlatformIO скачает платформу `espressif32` и тулчейн (несколько сотен МБ) — это нормально.
   Результат появится в `.pio/build/esp32-s3-devkitc-1/firmware.bin` — именно туда смотрит `wokwi.toml`.

3. В VS Code нажать `F1` → **Wokwi: Start Simulator**.
   Светодиод замигает раз в секунду, в окне Serial Monitor появятся `LED ON` / `LED OFF`.

После каждого изменения кода нужно снова выполнить `pio run`, затем перезапустить симулятор
(при повторном build Wokwi сам подхватывает свежую прошивку).

## Ошибка «firmware binary ... not found in workspace»

Это значит, что шаг 2 (`pio run`) ещё не выполнялся (или путь в `wokwi.toml` не совпал с папкой
`.pio/build/<env>/`). Собери проект и запусти симулятор снова.

## Особенность этой машины (macOS + Python 3.15)

На части машин `brew install platformio` подтягивает свежий Python (3.15), в котором
`platform.mac_ver()` возвращает пустую строку. Из-за этого встроенный `pip` падает на
установке `tool-esptoolpy` (`ValueError: invalid literal for int() with base 10: ''`),
и сборка обрывается ошибкой `MissingPackageManifestError`.

Рабочее решение — поставить PlatformIO в отдельное venv на Python с рабочим
`mac_ver()`:

```sh
python3 -c 'import platform; print(platform.mac_ver())'   # пусто → версия не годится

/opt/homebrew/bin/python3.14 -m venv ~/.platformio-venv   # или другую рабочую версию
~/.platformio-venv/bin/python -m pip install -U platformio
```

Makefile находит это venv сам, иначе берёт `pio` из PATH. Переопределить:
`make build PIO=/путь/к/pio`.

Чтобы `pio` работал и из терминала VS Code, можно добавить его в PATH (`~/.zprofile`):

```sh
echo 'export PATH="$HOME/.platformio-venv/bin:$PATH"' >> ~/.zprofile
```

После этого достаточно команды `pio run`.

> Эта поломка специфична для macOS и новых Python. На Linux и в CI (Ubuntu,
> Python 3.11) проблемы нет — там `pip install platformio` работает штатно.

## Проверка результата

- Светодиод мигает с периодом 1 секунда (1 сек горит, 1 сек не горит).
- Serial Monitor (115200 бод) показывает начало работы, число занятых клеток и поле:
  ```
  ESP32-S3 reed grid started (GPIO48, 4x4)
  grid: 0 closed
    A B C D
  1 . . . .
  2 . . . .
  3 . . . .
  4 . . . .
  ```
- Клик по кнопке (Cmd-клик на Mac держит её нажатой) даёт событие и перерисовку поля:
  ```
  cell A1 closed
  grid: 1 closed
    A B C D
  1 X . . .
  ...
  ```
  Cmd-клик по нескольким кнопкам — несколько фигур на поле одновременно.

## Проверка в симуляторе локально

`make sim` собирает прошивку и прогоняет сценарий `blink.test.yaml` в облаке Wokwi —
проверяются мигание и все шестнадцать клеток. Нужен токен `WOKWI_CLI_TOKEN` в окружении
(его не нужно класть в файл и тем более в репозиторий); без токена `make sim` просто
собирает прошивку и подсказывает запуск из VS Code. Serial прогона остаётся в `serial.log`.

`make check` токена не требует: сборка и native-тесты идут на хосте.

## Синхронизация с Wokwi (GitHub → симуляция)

Важно: **автоматической синхронизации «пуш в GitHub → проект на wokwi.com» не существует.**
У Wokwi две независимые вещи:

1. **Проект на wokwi.com** — то, чем делятся ссылкой (`https://wokwi.com/projects/<id>`).
   Авто-импорта из GitHub нет: код и `diagram.json` там обновляются вручную.
2. **Wokwi CI (GitHub Actions)** — по пушу собирает прошивку и прогоняет симуляцию в облаке
   (проверка, а не публичная ссылка).

### Ссылка для друзей (wokwi.com)

**Проект уже создан и опубликован:**

- **Ссылка:** <https://wokwi.com/projects/477978257402627073>
- **Название:** ESP32-S3 Blink (LED on GPIO48) · видимость **Public**

Друзья открывают ссылку и жмут **Play** прямо в браузере, ничего устанавливать не нужно.

При изменениях кода схему и код на wokwi.com нужно обновить вручную (копия кода лежит
в `sketch.ino`, схема — в `diagram.json`): открыть проект → вставить файлы → **Save**.
Ссылка при этом не меняется.

> Если проект менял AI-агент — он делает это сам, см. `AGENTS.md` (раздел 2). Там же описаны
> известные грабли браузерной автоматизации.

### Авто-проверка на GitHub (Wokwi CI)

В репозитории уже есть workflow `.github/workflows/wokwi.yml` и сценарий `blink.test.yaml`:
на каждый push/PR GitHub собирает прошивку (`pio run`) и прогоняет её в Wokwi CI, проверяя,
что LED мигает, а все шестнадцать клеток по очереди сообщают своё имя. Симуляция идёт по
прошивке PlatformIO (путь к ней в `wokwi.toml`), а не по `sketch.ino`.

Логи прогона в GitHub закрыты авторизацией, поэтому workflow на ветках `ci/**` и `main`
дополнительно коммитит `serial.log` и `wokwi-cli.log` в ветку `ci/reed-matrix-stand` — оттуда
их можно прочитать без входа в GitHub.

Чтобы включить, один раз добавь секрет:

1. Получить токен на <https://wokwi.com/dashboard/ci> (начинается с `wok_`, 44 символа).
2. GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
3. Имя: `WOKWI_CLI_TOKEN`, значение: токен.

Бесплатного тарифа хватает (50 минут симуляции в месяц). Результат видно во вкладке
**Actions** на GitHub.
