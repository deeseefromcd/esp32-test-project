# Proposal

## Why

GitHub Actions «Build and test on Wokwi» падал на шаге `Test with Wokwi`: симуляция
успешно подключалась к Wokwi Simulation API, но serial-вывод был пустым, и сценарий
`blink.test.yaml` не дожидался ни одной строки — ожидание истекало по таймауту.

Причина — схема `diagram.json` не подключала serial-монитор к плате. В отличие от
`wokwi-esp32-devkit-v1`, у платы `board-esp32-s3-devkitc-1` монитор не подключается
автоматически: нужны явные соединения на выводах TX/RX. Без них вывод прошивки
(включая загрузочный лог ROM) никуда не транслируется, и проверять его нечем.

## What Changes

- В `diagram.json` добавляются два соединения serial-монитора:
  `esp:TX` → `$serialMonitor:RX` и `esp:RX` → `$serialMonitor:TX`.
- Существующие соединения (GPIO48 → анод светодиода, катод → резистор 220 Ом → GND)
  не меняются.
- Прошивка, сценарий `blink.test.yaml` и workflow не меняются.
- После изменения схемы страница проекта на wokwi.com обновляется вручную, чтобы
  браузерная симуляция тоже показывала serial.

## Capabilities

### New Capabilities

- `wokwi-simulation`: контракт схемы симуляции — какие соединения обязаны существовать,
  чтобы вывод прошивки и уровень на пине светодиода были наблюдаемы в Wokwi
  и в Wokwi CI.
- `ci-verification`: контракт пайплайна проверки — что именно проверяется на каждый
  push и при каких условиях прогон считается успешным или упавшим.

### Modified Capabilities

Нет.

## Impact

- `diagram.json` — два новых соединения.
- Пайплайн `.github/workflows/wokwi.yml` начинает проходить (проверено: прогоны
  №2–№4 зелёные, падал только №1).
- Страница wokwi.com требует синхронизации `diagram.json` (см. `AGENTS.md`, раздел 2).
- Публичный контракт проекта (пин GPIO48, период 1000 мс, строки в serial) не меняется.
